## 目的

## 適用情境

當需求涉及功能判斷、限制條件、預設行為或產品規則時，AI Agent 應閱讀此文件。

## 目前內容

啟動、定時檢查、系統列重新整理與手動刷新都必須優先透過 Codex app-server 取得帳戶即時資料。即時查詢失敗時，若已有上一筆成功 live 值需先保留；沒有 live 值時才退回本機 session，且畫面需告知使用者目前顯示 fallback 狀態。

自動檢查約每 10 分鐘執行一次，且資料來源必須與手動刷新一致。Claude 啟動、自動檢查與手動刷新都使用 Claude Code CLI `/usage`，失敗時才退回既有快取資料來源。

成功取得的 Claude 即時值必須寫回記憶快取。CLI 暫時失敗時應保留最後一筆成功快取，不可將可用資料替換成錯誤狀態。

Codex 成功取得的即時結果不再只保留 5 分鐘。排程不得固定以本機 LOG 覆蓋畫面；LOG 僅能在沒有可用 live 結果且即時查詢失敗時作為 fallback。

## 2026-06-08 視窗停靠規則

Widget 的主要定位規則是靠近 Windows 時間與通知區，但不得覆蓋工作列。定位需使用 Electron `screen` 的 `workArea` 計算，避免在不同解析度或工作列高度下超出可用工作區。

從系統列叫出 Widget 時，應優先停靠到滑鼠所在螢幕的右下角；啟動與螢幕工作區變動時，則以主螢幕工作區重新計算位置。
